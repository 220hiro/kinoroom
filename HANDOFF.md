## 1. Контекст передачи проекта в Codex

Проект передаётся из Antigravity в **OpenAI Codex** на другом ChatGPT-аккаунте.
Все предыдущие эксперименты с внешними рекламными iframe (включая Шаг 2G с CineSrc / UnifiedCineSrcPlayer) **окончательно закрыты и откатаны**, так как при проверке на реальном iPhone CineSrc показал всплывающую рекламу.

**Ключевая цель KinoRoom**: Личный онлайн-кинотеатр для владельца и друзей. Видео должно воспроизводиться в собственном `KinoRoomPlayer` быстро, без рекламы, с выбором реальной озвучки, выбором качества и автоматическими русскими субтитрами.

## 2. Фактическое состояние проекта

### ✅ Что работает и подтверждено тестами (A: ACTIVE / KEEP):
1. **Каталог и поиск TMDB**:
   - `src/lib/providers/metadata.ts`, `src/app/page.tsx`, `src/app/catalog/page.tsx`, `src/app/search/page.tsx`.
   - Постеры, описания, списки актеров, детальная страница тайтла (`/title/[type]/[id]`), выбор сезонов и эпизодов для сериалов.
2. **Локальные закладки и история**:
   - `src/lib/storage.ts`: сохранение закладок и позиции просмотра (таймкоды) в `localStorage`.
3. **Нативный HLS-плеер КиноРум**:
   - `src/components/player/KinoRoomPlayer.tsx`: HTML5 Video + `hls.js`, кастомный таймлайн, громкость, полноэкранный режим.
   - Воспроизведение открытых лицензированных потоков (Blender CC-BY: Tears of Steel, Big Buck Bunny; Public Domain: Night of the Living Dead).
   - Честность Playback API: для неизвестных коммерческих фильмов без потока строго возвращается `HTTP 404 SOURCE_UNAVAILABLE` (без подмены другим фильмом).
4. **Автоматические русские субтитры (Шаг 2F)**:
   - `SubDLProvider` (`src/lib/services/subdl.ts`): SubDL API v2 с распаковкой ZIP (`fflate`) и автодекодированием кириллицы (UTF-8, UTF-16, Windows-1251 / CP1251).
   - `OpenSubtitlesProvider` (`src/lib/services/openSubtitles.ts`): автоматический fallback при `NOT_FOUND` в SubDL с кэшированием токена (23ч) и запросов, SSRF-защитой.
   - `ExternalSubtitleEngine` (`src/lib/playback/externalSubtitleEngine.ts`): парсер SRT/VTT, санитайзинг, синхронизация по времени, регулировка сдвига `-60..+60с`.
   - **Безопасность API-ключей**: Все захардкоженные fallback-ключи полностью удалены из кода. Ключи читаются строго из серверных переменных `SUBDL_API_KEY` и `OPENSUBTITLES_API_KEY` (на сервере Vercel/VPS/Docker). При отсутствии ключа честно возвращается статус `REQUIRES_KEY`. Старые ключи из истории Git подлежат отзыву и перевыпуску владельцем.
5. **Торрент-модуль**:
   - `src/app/torrent/page.tsx`: поиск раздач по трекерам (RuTracker, Rutor, NnmClub).
   - `src/lib/services/torrents.ts` и `src/app/api/torrent/stream/route.ts`: WebTorrent движок со стримингом HTTP 206 Partial Content.
   - `src/components/player/TorrentPlayer.tsx`: плеер со статистикой пиров, скорости и буферизации.
6. **Внешний fallback-источник**:
   - `src/components/player/OnlinePlayer.tsx`: внешний источник EmbedWave Cinesrc с наложенным оверлеем субтитров (сохранён для совместимости).

## 3. Последнее наблюдение пользователя и известная проблема

### ⚠️ Проблема с торрент-потоком:
При последней проверке пользователь наблюдал воспроизведение видеопотока через собственный плеер с индикатором «Торрент-поток» (24 пира, скорость 2.4 МБ/с).
**Однако**:
- Видео **очень долго начинает воспроизводиться** (долгий старт до первого кадра).
- Видео **периодически буферизуется и замирает**.
- **Отсутствует полноценный выбор озвучки** (если в торрент-контейнере несколько дорожек).
- **Отсутствуют субтитры** в этом режиме.
- **Отсутствует полноценный выбор качества** (воспроизводится один исходный поток из торрента).

## 4. Следующие задачи для OpenAI Codex

### Задача №1 (Приоритет 1): Исследовать причины медленного старта и буферизации торрент-потока
1. Изучить `src/lib/services/torrents.ts` и `src/app/api/torrent/stream/route.ts`.
2. Проверить стратегию скачивания чанков:
   - Включён ли режим `file.select()` с правильными приоритетами?
   - Скачиваются ли куски строго последовательно (`sequential pieces`), или WebTorrent запрашивает случайные куски роя?
   - Как скачивается мета-заголовок контейнера (для MP4 — `moov atom`, для MKV — cluster index)? Если `moov` находится в конце файла, плеер блокируется до полной загрузки файла!
3. Проверить работу буфера и кэширования в памяти/на диске.
4. Оценить разницу между локальным WebTorrent в процессе Next.js и выделенным инстансом TorrServer (`TORRSERVER_URL`).

### Задача №2 (Приоритет 2): Реализация выбора аудиодорожек и встроенных субтитров
1. Исследовать форматы торрент-раздач: большинство фильмов упакованы в MKV с несколькими дорожками (дубляж, закадровый, оригинал).
2. Выяснить, как извлекать доступные аудиодорожки и субтитры без зависания браузера.
3. Проверить поддержку кодеков на iPhone Safari (AAC/MP3 поддерживаются нативно, AC3/EAC3/DTS требуют транскодирования или MP4-релизов).

### Задача №3 (Приоритет 3): Адаптивное качество
1. Оценить возможность переключения между разными торрент-раздачами (1080p, 720p, MP4-мобильная) прямо из меню плеера KinoRoomPlayer.

## 5. Чего категорически НЕ делать

1. ❌ **НЕ возвращаться к рекламным iframe** (CineSrc, EmbedWave, Kinobox и др.). Эксперимент 2G закрыт.
2. ❌ **НЕ создавать параллельный второй плеер**. Оптимизировать существующий `KinoRoomPlayer`.
3. ❌ **НЕ делать масштабных рефакторингов** каталога, TMDB, закладок или роутинга Next.js.
4. ❌ **НЕ имитировать озвучку или качество**. Показывать только подтверждённые данные.
5. ❌ **НЕ удалять и не ломать Шаг 2F** (`SubDLProvider`, `OpenSubtitlesProvider`, `ExternalSubtitleEngine`).
6. ❌ **НЕ коммитить секреты** в Git.
